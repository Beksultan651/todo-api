# Менеджер задач (CRUD + API)

Приложение на HTML, CSS и обычном JavaScript. React, сборка, установка пакетов
и API-ключ не нужны. Интерфейс на русском, комментарии в коде на казахском.

## Запуск

1. Распакуйте архив и откройте папку с четырьмя файлами в VS Code.
2. Откройте `index.html` через расширение **Live Server**.
3. Дождитесь загрузки пользователей и первых 30 задач или нажмите
   **«Загрузить задачи ↓»**.

Можно открыть `index.html` напрямую, но для предсказуемого localStorage
рекомендуется локальный HTTP-сервер. При дальнейшей работе используйте тот же
адрес и порт: localStorage привязан к адресу сайта и профилю браузера.
Для запросов к DummyJSON нужен интернет.

## Возможности

- Загрузка задач по HTTPS-ссылке, индикатор загрузки, результат и ошибки API.
- Статистика загруженных задач, поиск текста, сортировка А–Я/Я–А,
  фильтры автора и статуса, сброс фильтров, счетчик «Показано N из M».
- Отдельная сортировка пользователей A–Z/Z–A, поиск имени и точного User ID.
  ID ищется кнопкой «Найти» или Enter.
- Нажатие на автора или карточку открывает профиль: данные слева,
  все задачи пользователя справа. На узком экране разделы идут друг за другом.
- Отдельные окна добавления, изменения и подтверждения удаления.
  Текст, автор и статус изменяются вместе. При смене автора задача переходит
  в профиль нового пользователя.
- При добавлении из профиля автор выбран автоматически; его можно изменить.
- Верхнее окно закрывается через ×, «Отмена», Escape или браузерную кнопку
  «Назад». Профиль под окном редактирования остается открытым.
- History API поддерживает Back/Forward без повторного `history.back()`.
  Поиск, фильтры, сортировка и позиции прокрутки восстанавливаются.

## API и поддерживаемые ссылки

По умолчанию: `https://dummyjson.com/todos?limit=30`.
Кнопка **DummyJSON** возвращает эту ссылку в поле, а загрузка выполняется
отдельной кнопкой. В поле вводится URL, а не секретный ключ.

Поддерживаются `https://dummyjson.com/todos` и
`https://dummyjson.com/todos/user/ID` с необязательными параметрами `limit`,
`skip`, `sortBy=todo` и `order=asc/desc`. Другие адреса и параметры отклоняются
с понятным сообщением. Сортировка элементами интерфейса выполняется в браузере.

Запросы приложения:

- `GET /users?limit=0` — все пользователи.
- `GET /users/{id}` — подробный профиль.
- `GET /todos/user/{id}?limit=0` — все задачи пользователя, независимо
  от первых 30 задач основного списка.
- `POST /todos/add` — имитация добавления.
- `PATCH /todos/{id}` — имитация изменения текста, автора или статуса.
- `DELETE /todos/{id}` — имитация удаления.

Источники: [документация задач](https://dummyjson.com/docs/todos),
[документация пользователей](https://dummyjson.com/docs/users).
В профиле показываются только явно перечисленные поля. Пароли, банковские
данные, SSN, токены и прочие секретные поля в интерфейс не выводятся.

## Сохранение и общий список

DummyJSON **не сохраняет изменения на сервере**. После успешного ответа API
приложение сохраняет измененные задачи в localStorage под ключом
`is.task-manager.v2`. Обновление страницы в том же браузере восстанавливает
эти изменения.

Основной список и профиль используют одну коллекцию задач. В основном списке
показывается загруженная API-выборка плюс созданные и измененные локально задачи.
Открытие профиля само по себе не расширяет основную выборку. Измененная задача
из полного профиля становится видна и в основном списке.

При объединении с сервером задачи сопоставляются по стабильному ключу
`api-ID`, а локальные правки имеют приоритет над исходным ответом API.
Для удаленных серверных задач хранятся их ID, поэтому новая загрузка
или открытие другого профиля не возвращает их в список.

Новые задачи получают уникальный ключ `local-…`: возвращаемый DummyJSON ID
может повторяться. Сервер не знает о новых записях, поэтому дальнейшее
редактирование, переключение статуса и удаление новых задач выполняются
локально, без обращения к несуществующему серверному ID.

Хранятся только изменения задач и ID удаленных задач. Полные профили
пользователей в localStorage не записываются. Если хранилище недоступно,
приложение сообщает об этом: текущий сеанс работает, но восстановление
изменений после обновления не гарантируется.

## Проверка

Проверено реальными HTTP-запросами к DummyJSON:

- Получение 30 задач, всех пользователей, отдельного профиля и его задач.
- Успешные POST, PATCH и DELETE; последующий GET подтвердил, что серверные
  данные остались исходными.

Проверено автоматическими DOM-тестами с контролируемыми ответами API:

- Поиск, обе сортировки задач и пользователей, фильтры автора и статуса.
- Открытие автора, поля профиля, отсутствие секретных полей, полная загрузка
  профиля сверх исходных 30 задач и пустой профиль.
- Добавление, изменение текста/автора/статуса, перенос между профилями,
  удаление с подтверждением и синхронизация обоих списков.
- Уникальные локальные ключи при повторяющемся серверном ID, локальное
  редактирование/отметка/удаление новых задач.
- Повторный запуск с сохраненным localStorage, отсутствие дублей и повторного
  появления удаленных задач, обработка поврежденного и недоступного хранилища.
- Ошибки загрузки, неподдерживаемые URL, повторная загрузка, откат при ошибке
  изменения и сохранение введенного текста при ошибке добавления.
- ×, «Отмена», Escape, настоящие переходы истории JSDOM Back/Forward,
  закрытие только верхнего окна, сохранение черновика, фильтров и прокрутки.
- CSS разобран парсером; проверены правила порядка колонок, ограничения
  высоты окна и перестроения на узком экране.

**Не проверено визуально:** совпадение с четырьмя исходными скриншотами и
отрисовка на реальном телефоне. Сами четыре изображения не доступны в
переданной папке вложений; внешний вид подготовлен по текстовому описанию.
К встроенному браузеру ранее применилось ограничение безопасности,
поэтому DOM/CSS-тесты не считаются полноценной визуальной проверкой.
